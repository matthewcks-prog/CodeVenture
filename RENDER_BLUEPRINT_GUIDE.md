# Render Blueprint Deployment Guide 🚀

## What is Infrastructure as Code (Blueprint)?

Render Blueprints allow you to define your entire infrastructure (web services, databases, environment variables) in a single `render.yaml` file. This is the **recommended approach** because:

✅ **Version Control**: Your infrastructure is stored in Git  
✅ **Reproducibility**: Easy to recreate or deploy to different environments  
✅ **Automation**: Database and web service are deployed together  
✅ **No Manual Steps**: Render automatically provisions everything

## Deployment Steps

### Step 1: Push to GitHub

First, commit all changes:

```bash
git add .
git commit -m "chore: configure Render Blueprint for production deployment"
git push origin main
```

### Step 2: Deploy via Render Dashboard

1. **Go to Render Dashboard**: https://dashboard.render.com

2. **Click "New +" → "Blueprint"**

3. **Connect Your Repository**:
   - Select "Connect GitHub"
   - Authorize Render to access your repositories
   - Choose `CodeVenture` repository
   - Select the `main` branch

4. **Review Blueprint**:
   - Render will detect `render.yaml`
   - You'll see:
     - ✅ Database: `codeventure-db` (PostgreSQL)
     - ✅ Web Service: `codeventure` (Python)
   - Click "Apply"

5. **Set Required Environment Variables**:
   
   Render will prompt you to set these **REQUIRED** variables:

   ```bash
   # Your production domain (update after first deploy if needed)
   DJANGO_ALLOWED_HOSTS=your-app-name.onrender.com
   
   # Your production domain with https:// prefix
   DJANGO_CSRF_TRUSTED_ORIGINS=https://your-app-name.onrender.com
   ```

   **Note**: The `DJANGO_SECRET_KEY` will be auto-generated by Render (marked as `generateValue: true` in render.yaml)

6. **Start Deployment**:
   - Click "Create Services"
   - Render will:
     - ✅ Create PostgreSQL database (2-3 minutes)
     - ✅ Deploy web service (5-10 minutes)
     - ✅ Run migrations automatically
     - ✅ Collect static files

### Step 3: Update Environment Variables

After the first deployment completes:

1. **Get Your Render URL**:
   - In Render Dashboard → `codeventure` service
   - Copy the URL (e.g., `https://codeventure-abc123.onrender.com`)

2. **Update Environment Variables**:
   - Go to Service → Environment
   - Update these values with your actual URL:
     ```
     DJANGO_ALLOWED_HOSTS=codeventure-abc123.onrender.com
     DJANGO_CSRF_TRUSTED_ORIGINS=https://codeventure-abc123.onrender.com
     ```
   - Save changes (this will trigger a redeploy)

### Step 4: Verify Deployment

Once deployed, verify everything works:

1. **Visit Your App**:
   - Open `https://your-app-name.onrender.com`
   - ✅ Homepage should load with CSS/images
   - ✅ Login/signup should work
   - ✅ No 500 errors

2. **Check Logs**:
   - Dashboard → `codeventure` service → Logs
   - Look for: `Booting worker with pid`
   - No errors about missing environment variables

3. **Create Superuser** (Optional):
   ```bash
   # In Render Dashboard → codeventure → Shell
   python manage.py createsuperuser
   ```

4. **Run Deployment Check**:
   ```bash
   # In Render Shell
   python manage.py check --deploy
   ```

## What Happens on Each Deploy?

Every time you push to GitHub, Render automatically:

1. ✅ Pulls latest code
2. ✅ Installs dependencies (`pip install -r requirements.txt`)
3. ✅ Collects static files (`collectstatic`)
4. ✅ Runs database migrations (`migrate`)
5. ✅ Starts Gunicorn with 2 workers
6. ✅ Connects to PostgreSQL database

## Environment Variables Reference

### Auto-Configured (No Action Needed)

These are automatically set by `render.yaml`:

```bash
PYTHON_VERSION=3.11.7
DJANGO_SETTINGS_MODULE=CodeVenture.settings
DJANGO_DEBUG=false
WEB_CONCURRENCY=2
DATABASE_URL=<auto-generated-by-render>
DJANGO_SECRET_KEY=<auto-generated-by-render>
```

### Required by You

You must set these in Render Dashboard:

```bash
# Update with your actual Render URL after first deploy
DJANGO_ALLOWED_HOSTS=your-app-name.onrender.com
DJANGO_CSRF_TRUSTED_ORIGINS=https://your-app-name.onrender.com
```

### Optional (For Google OAuth)

If you want Google Sign-In:

1. Go to [Google Cloud Console](https://console.cloud.google.com)
2. Create OAuth 2.0 credentials
3. Add authorized redirect URI: `https://your-app-name.onrender.com/accounts/google/login/callback/`
4. In Django admin, add Social Application with your Client ID and Secret

## Troubleshooting

### Build Fails

**Check build logs** (Dashboard → Service → Logs):

- ❌ **"Could not find a version that satisfies..."**  
  → Check `requirements.txt` for incompatible versions
  
- ❌ **"No module named 'django'"**  
  → Ensure `requirements.txt` is in the root directory

### 500 Internal Server Error

1. **Check Logs** for detailed error message
2. **Common causes**:
   - `DJANGO_ALLOWED_HOSTS` not set correctly
   - `DJANGO_CSRF_TRUSTED_ORIGINS` missing `https://`
   - `DATABASE_URL` not connected

### Static Files Not Loading

- Verify `collectstatic` ran successfully in build logs
- Check `DJANGO_ALLOWED_HOSTS` includes your domain
- WhiteNoise should be in `MIDDLEWARE` (already configured)

### Database Connection Issues

- Ensure database is in the same region as web service (Ohio)
- Check `DATABASE_URL` is set in Environment tab
- Verify migrations completed successfully
